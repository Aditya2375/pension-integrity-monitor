# Portal security integration contract

No application or template changes are made by the security support package.

1. `security.web.install_csrf(app)` once, after app creation. Every POST form, including login and public appeal lookup/submission, needs `<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">`. Unsafe JSON clients supply `X-CSRF-Token`. Missing/wrong tokens return 400 before route logic. Do not exempt routes. Logout becomes POST; session.clear() rotates credentials and tokens after authentication changes. Add no-store to sensitive errors too.
2. Call `client_ip(request.remote_addr, request.headers.get('X-Forwarded-For'), configured_cidrs)`. Empty proxy allowlist is the safe default. Edge must overwrite client headers. Do not trust `X-User`, `X-Roles` or forwarded HTTPS claims from arbitrary peers. Set HSTS/TLS at the edge; verify Secure cookie issuance through the actual proxy.
3. `Limiter(path).allow(bucket, limit, window_seconds)` is an atomic, process-shared single-host fixed-window control, with 10,000-bucket cap, 24-hour expiry and fail-closed storage errors. Fixed-window boundary bursts are possible. Use separate scope prefixes for login and appeals, pseudonymized IP keys, plus account/global limits. Multi-host requires centrally atomic edge limits. It is not a complete anti-abuse service.
4. `Principal` comes only from a validated identity-provider adapter, never user-submitted attributes. Map a named subject, roles and jurisdictions. Call `authorized` before every query or mutation, including exports. `independent_approval` rejects the same proposer/approver subject. The synthetic shared-key demo must explicitly say it is not production identity.
5. `security.audit.initialize(conn)` prepares a separate append-only table; `append(conn, actor, action, object_ref)` participates in the caller transaction. Do not commit a business mutation without its audit event. Event fields contain bounded identifiers, never free-text evidence, Aadhaar/PAN, session/appeal tokens or secrets. Store evidence hashes/references and preserve evidence in a restricted store. Serialize writers and export (seq, hash) checkpoints to an independently controlled append-only destination. `verify` must receive that checkpoint; without it whole-chain rewrite and tail deletion can go undetected. Old `audit` rows are not automatically protected.
6. Use `csv_cell` on every textual export cell before csv.writer. Numeric scores can remain numeric. Quoting CSV alone does not stop spreadsheet formulas.
7. Mutations require existing scoped objects, allowed state transitions, complete expected verification set, reasons and a second officer for adverse recommendations. Zero verification rows is failure, not approval. One atomic appeal release path must update review state and create a reinstatement REQUEST; never claim a payment was made. Preserve all source feed statuses unchanged. Record review state in derived tables.
8. Validate settings as finite, bounded numbers; reject unknown/nonfinite/negative costs and invalid appeal windows without partial writes. Reject invalid dates, duplicate headers and oversized fields at intake. Do not expose parser exceptions or feed contents to a public response.
9. Tests must exercise integrated routes with CSRF enabled. Unit tests of supporting modules do not prove application enforcement. Freeze the exact commit for review; old security statements are superseded by the new release verdict.
